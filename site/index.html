The Git Mistakes Rescue Handbook

A beginner manual for recovering from git panic — by Asdale Dynamics, LLC

Git has a reputation for being scary. It isn't, really. It's just a very literal diary of your project, and almost every "I've ruined everything" moment in git is reversible. Git is designed to not lose your work. The hard part is knowing which few commands get you back to safety.

This handbook is written like a friend explaining it across the kitchen table: plain English, step by step, never condescending. Every chapter starts with "what you're feeling," tells you the one thing to do first, and then walks through the fix calmly.

The golden rule of git panic: don't delete anything, don't re-clone, and don't run anything with `--force` until you've read one chapter of this book. Your work is almost certainly still on your disk.

How to use this book

  1. Find your situation in the decision table below.
  2. Read the one-line "do this first" move.
  3. Open the linked chapter, breathe, follow the steps.

You never need to memorize anything. Git experts don't memorize either — they just know this table by heart.

Three habits that end 90% of future panics

  1. Commit early, commit ugly. A commit named "wip messy draft" on a

throwaway branch costs you nothing and saves everything. Nobody grades your commits.

  1. Make a "backup branch" before anything scary. git branch backup-just-in-case

before you rebase, reset, or merge. It's a bookmark pointing at where you are right now, and you can never lose anything the bookmark points to.

  1. Learn `git reflog`, not `--force`. The reflog (Chapter 7) is git's

own undo button. Almost every "vanished" disaster is a two-command fix.

What this book is not

  • It is not exhaustive. It covers the panics, not all 150 subcommands.
  • It is not medical, legal, or financial advice — and it's not even

official git advice. It's experience, explained plainly. When in doubt, make a backup branch and copy your folder somewhere safe first.

  • It never asks you to trust a command blindly. Every chapter explains

what the command actually does before you run it.
